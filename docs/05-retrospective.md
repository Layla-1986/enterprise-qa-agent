# 复盘

## 最难的问题

企业制度可能同时存在不同规定。检索命中本身不能证明某条制度适用，因此需要读取原文并检查是否存在冲突；缺少适用范围和优先级时，应呈现不同依据并请求确认，而不是仅依据日期选择答案。

## 学习收获

1. **RAG 与证据溯源**：理解了从问题检索候选片段、读取原文，到生成答案并附带来源的过程；检索召回、引用是否存在，以及答案是否被证据支持，是需要分别评估的问题。
2. **Agent 与工具调用**：理解模型如何选择检索、读取或结束，观察工具结果后调整下一步；工具失败、证据不足和执行上限需要明确处理。
3. **LangChain**：学习了模型、提示词、检索器及工具的组合方式，以及将模型调用与外部数据和工具连接的思路。
4. **LangGraph**：学习了用状态、节点和条件边描述多步骤流程，并理解检查点和人工介入可用于需要暂停、恢复或审查的场景。
5. **效果评估**：认识到需要分别检查正常答案、冲突、资料不足、工具失败、改写、追问和资料变化，并保留失败记录。

LangChain 和 LangGraph 是相关学习内容；**本项目采用 Python 标准库实现，没有接入或运行这两个框架**。

## 已知限制与下一步

本轮发现模糊问题可能被误判为报销问题，保留失败记录后增加了澄清指令；在 9 条自拟检索样本上比较了同义词归一化与未归一化的基线，结果和局限见评估文档。当前字符检索可能遗漏相关资料；原文子串校验不能证明语义支持；模型输出偶发格式错误。可继续构建标注测试集，评估召回与误答，改进检索和重排，并研究语义支持校验、权限隔离及提示注入防护。

实际用时：2 小时 30 分钟（150 分钟），由候选人提供。
