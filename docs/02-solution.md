# 设计

CLI → 模型动作 → search/read 工具 → 结果反馈模型 → 下一动作或 finish。模型每次输出 JSON；系统提示要求检索后读取、处理冲突、仅引用原文。程序要求先检索，且只允许读取检索结果中的片段；按文档和片段 ID 缓存已读内容，检查引用为非空逐字子串并补充版本日期；冲突引用须来自不同片段，非法引用反馈模型修正。工具异常反馈模型，由模型决定重试或结束；上限防止无限循环。模型/解析异常返回 model_error。

检索使用字符二元组匹配和少量同义词归一化，按命中数排序返回所有匹配片段；read 从磁盘重新读取。无向量库和第三方框架，便于本地运行。此检索不保证召回，排序靠前不代表权威；日期也不自动决定优先级。引用的字符串校验不能保证语义蕴含或穷尽冲突，模型可能漏检、误判，实际部署需检索评估、权限过滤及人工复核。文档内容是数据而非指令；当前尚无完整提示注入防护。

为避免遗漏已检索到的候选证据，`answered` 要求本次检索返回的片段均已读取，且失败的工具调用已用相同参数成功恢复；否则模型需继续核查或返回资料不足。该规则偏保守，噪声结果较多时可能消耗步数并返回 incomplete。冲突状态允许在未读完全部结果时报告已发现的冲突，不能证明其他冲突已经穷尽。检索未命中的资料仍可能遗漏，不能保证真实环境无冲突。

当问题缺少必要主题且历史无法确定时，提示模型先请求澄清；这不是程序层面的语义强制约束。检索评估使用合成小样本和无同义词的字符二元组基线，指标及限制见评估文档。

模型结束动作还需满足非空文本答复、字符串列表形式的资料缺口及引用字段类型检查；无效输出反馈给模型修正，若到达步数上限则返回 incomplete。以上检查只验证格式与原文存在，不验证语义支持。
